## Das Dataset: ein Katalog mit Zugriffsnummern

Bleiben wir zunächst bei den Federdaten und erzeugen sie noch einmal:

```{code-cell} python
import torch

torch.manual_seed(42)

n = 200
s = torch.rand(n, 1) * 100.0                  # Federweg in mm
F = 0.05 * s + 4e-5 * s**3                    # wahre Kennlinie in N
F = F + torch.randn(n, 1) * 2.0               # Messrauschen
```

Ein **Dataset** (englisch: "Dataset") ist in PyTorch ein Objekt, das genau zwei Fragen beantworten kann: *Wie viele Beispiele gibt es?* und *Gib mir Beispiel Nummer i.* Mehr nicht. Man kann es sich wie einen Bibliothekskatalog vorstellen: Der Katalog enthält nicht alle Bücher auf einmal aufgeschlagen, sondern weiß nur, wie viele es gibt und wie man jedes einzelne beschafft. Technisch implementieren wir dafür eine Klasse mit den Methoden `__len__` und `__getitem__`:

```{code-cell} python
from torch.utils.data import Dataset

class FederDataset(Dataset):
    def __init__(self, s, F):
        self.s = s
        self.F = F

    def __len__(self):
        return len(self.s)

    def __getitem__(self, idx):
        return self.s[idx], self.F[idx]

dataset = FederDataset(s, F)
print(len(dataset))
print(dataset[0])
```

Bei unseren Federdaten wirkt das wie unnötiger Zeremoniell, denn die Tensoren liegen ja längst im Speicher. Der Wert dieser Schnittstelle zeigt sich später: Bei Bilddaten lädt `__getitem__` das jeweilige Foto erst in dem Moment von der Festplatte, in dem es gebraucht wird. Die Trainingsschleife merkt davon nichts, weil sie nur mit dem Katalog spricht. Genau diese Entkopplung von Datenquelle und Training ist der Zweck der Dataset-Klasse.

## Der DataLoader: Pakete packen

Der zweite Baustein ist der **DataLoader** (englisch: "DataLoader"). Er nimmt ein Dataset entgegen und liefert daraus Pakete fester Größe, sogenannte **Batches** (englisch: "Batches"). Die Paketgröße heißt **Batch Size**.

```{code-cell} python
from torch.utils.data import DataLoader

loader = DataLoader(dataset, batch_size=32, shuffle=True)

s_batch, F_batch = next(iter(loader))
print(s_batch.shape, F_batch.shape)
```

Der erste Batch enthält 32 Messpunkte, fertig gestapelt zu Tensoren der Form `(32, 1)`. Das Argument `shuffle=True` mischt die Reihenfolge der Beispiele vor jeder Epoche neu. Das ist bei Messdaten wichtig, die in sortierter Reihenfolge aufgenommen wurden (zum Beispiel mit aufsteigendem Federweg): Ohne Shuffling sähe das Netz in jedem Batch nur einen Ausschnitt des Wertebereichs und würde systematisch in eine Richtung gezogen.

```{admonition} Mini-Übung

```

```{code-cell} python
for i, (s_batch, F_batch) in enumerate(loader):
    print(f"Batch {i + 1}: {len(s_batch)} Beispiele")
```

```{admonition} Lösung
:class: tip
:class: dropdown
Es sind 7 Batches: sechs volle Batches mit je 32 Beispielen (zusammen 192) und ein Rest-Batch mit 8 Beispielen. Der DataLoader wirft den Rest also nicht weg, sondern liefert ihn als kleineres letztes Paket. Wer das nicht möchte, kann mit dem Argument `drop_last=True` den unvollständigen Batch verwerfen.
```

## Warum Batches?

Der Speicher war unser Aufhänger, aber er ist nicht der einzige Grund. Trainieren wir auf dem ganzen Datensatz, bekommen wir pro Epoche genau eine Gradientenberechnung und damit genau einen Lernschritt. Mit Batches der Größe 32 macht das Netz bei 200 Beispielen sieben Schritte pro Epoche, bei 50.000 Bildern über 1.500. Das Netz lernt also pro Datendurchlauf deutlich öfter.

Dafür zahlen wir einen Preis: Der Gradient eines Batches ist nur eine Schätzung des "wahren" Gradienten über alle Daten, und diese Schätzung rauscht. Das Prinzip kennen wir aus der Qualitätssicherung: Statt jedes gefertigte Teil zu vermessen, ziehen wir eine Stichprobe und akzeptieren dafür eine gewisse Unsicherheit. Beim Training neuronaler Netze hat sich gezeigt, dass dieses Rauschen oft sogar hilft, weil es die Optimierung aus schlechten flachen Regionen der Loss-Landschaft herausschütteln kann. Das Verfahren heißt **Mini-Batch Gradient Descent** und ist der Standardfall im Deep Learning; Training auf dem vollen Datensatz ist die Ausnahme für kleine Probleme.

Die Trainingsschleife ändert sich nur um eine innere Schleife über die Batches:

```{code-cell} python
import torch.nn as nn

torch.manual_seed(42)

class FederNetz(nn.Module):
    def __init__(self):
        super().__init__()
        self.schichten = nn.Sequential(
            nn.Linear(1, 16),
            nn.ReLU(),
            nn.Linear(16, 1),
        )

    def forward(self, x):
        return self.schichten(x)

modell = FederNetz()
criterion = nn.MSELoss()
optimizer = torch.optim.Adam(modell.parameters(), lr=0.05)

loss_verlauf = []

for epoche in range(100):
    loss_summe = 0.0
    for s_batch, F_batch in loader:
        F_pred = modell(s_batch)
        loss = criterion(F_pred, F_batch)
        optimizer.zero_grad()
        loss.backward()
        optimizer.step()
        loss_summe += loss.item() * len(s_batch)

    loss_verlauf.append(loss_summe / len(dataset))
    if (epoche + 1) % 25 == 0:
        print(f"Epoche {epoche + 1:3d}: mittlere Loss = {loss_verlauf[-1]:.2f}")
```

Die fünf Kernzeilen sind exakt dieselben wie in der letzten Sektion, sie arbeiten jetzt nur auf einem Batch statt auf allen Daten. Neu ist lediglich die Buchhaltung: Wir mitteln die Batch-Losses gewichtet über die Epoche, damit der protokollierte Wert mit dem Training auf dem vollen Datensatz vergleichbar bleibt.

## Dasselbe Problem, zwei Werkzeuge

Neuronale Netze sind nicht das einzige Werkzeug für Lernprobleme auf tabellarischen Daten. Die Python-Bibliothek **scikit-learn** versammelt die Verfahren des klassischen Machine Learning, von der linearen Regression bis zu Entscheidungsbäumen, hinter einer bemerkenswert einheitlichen Schnittstelle: Modell anlegen, `fit` aufrufen, `predict` aufrufen. Unsere Federkennlinie lernt dort zum Beispiel ein kleines neuronales Netz in drei Zeilen:

```{code-cell} python
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.neural_network import MLPRegressor

mlp = make_pipeline(StandardScaler(),
                    MLPRegressor(hidden_layer_sizes=(16,), max_iter=20000,
                                 random_state=42))
mlp.fit(s.numpy(), F.numpy().ravel())
print(f"Bestimmtheitsmaß R²: {mlp.score(s.numpy(), F.numpy().ravel()):.3f}")
```

Vier Zeilen statt Dataset, DataLoader und Trainingsschleife, und das Ergebnis ist auf diesen Daten genauso brauchbar (der `StandardScaler` übernimmt dabei die Standardisierung der Eingangsgröße, die wir in PyTorch von Hand erledigen würden). *Wozu also der ganze PyTorch-Aufwand?* Die ehrliche Antwort: Für ein Problem wie unsere Federkennlinie lohnt er sich nicht. Klassisches Machine Learning ist auf kleinen und mittleren tabellarischen Datensätzen oft genauso gut oder besser, schneller trainiert und einfacher zu bedienen. Der Aufwand von PyTorch zahlt sich dort aus, wo scikit-learn an Grenzen stößt: bei Bildern, Audio und Text, bei sehr großen Datenmengen, bei Training auf der GPU und überall dort, wo wir die Architektur des Netzes selbst gestalten müssen, statt eine Standardarchitektur zu konfigurieren. Als grobe Landkarte:

| Situation | Werkzeug der Wahl |
| ------------------------------------------------------------ | ----------------------------- |
| Tabellarische Daten, bis einige zehntausend Zeilen           | klassisches ML (scikit-learn) |
| Bilder, Audio, Text, Sensor-Zeitreihen in großer Menge       | Deep Learning (PyTorch)       |
| Eigene Architekturen, GPU-Training, volle Kontrolle          | Deep Learning (PyTorch)       |
| Schnelle Baseline, um den Nutzen von Deep Learning zu prüfen | klassisches ML (scikit-learn) |

Die letzte Zeile ist als Arbeitsweise gemeint: Eine klassische Baseline in wenigen Zeilen zeigt uns, welches Fehlerniveau "billig" erreichbar ist. Erst wenn ein neuronales Netz diese Baseline deutlich schlägt, rechtfertigt es seinen Mehraufwand. Diese Denkweise nehmen wir in die Projektphase mit. ## Zusammenfassung und Ausblick

Mit Dataset und DataLoader haben wir die Datenversorgung des Trainings auf ein Fundament gestellt, das vom Federprüfstand bis zum Bilddatensatz der Projektphase trägt: Das Dataset beantwortet "wie viele und gib mir Nummer i", der DataLoader packt daraus gemischte Batches, und die Trainingsschleife bleibt bis auf eine innere Schleife unverändert. Batches sparen nicht nur Speicher, sondern geben dem Netz viele Lernschritte pro Epoche, um den Preis verrauschter Gradienten. Außerdem haben wir unser neues Werkzeug eingeordnet: Für kleine tabellarische Probleme bleibt klassisches ML die erste Wahl, Deep Learning spielt seine Stärken bei Bildern, großen Datenmengen und eigenen Architekturen aus. Damit steht das komplette Grundgerüst: Modell, Loss, Optimizer, Daten. In Kapitel 5 machen wir aus "das Training läuft" ein "das Training läuft gut": Learning Rate, Validierungsdaten, Overfitting und die Diagnose kranker Lernkurven.
